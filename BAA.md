# Baa-ton operating contract

Apply this contract only when using Baa-ton for the current task. It does not turn every session into an orchestration root.

The human can direct any session. Their current instruction overrides an older assigned task. There is no root-only human authority. Record a direct intervention as a new job revision before submitting a result; a worker recording its own redirection must not prompt itself again.

Use explicit configured scopes, profiles and job IDs. Separate personal/work accounts by the authorized workspace and account context, not by assumptions about machine ownership. Distinct asks use fresh assignments; continuation of the same work stays with its job. Respect an explicitly selected model and the user's configured defaults without changing global settings.

HERDR owns process/terminal/worktree lifecycle. Baa-ton owns only its scope's goal, jobs, messages, evidence, approval requests and short chains. Pause is local and gates new automation. Never turn pause into Ctrl-C or cancel into deletion.

Preserve native permission mechanisms. The editable ask-list controls additional tool confirmations, not provider restrictions or authorization for unrelated actions. External publication still requires the applicable authorization. The Claude broker accepts only verified native-session non-Bash requests. Never turn worker text into approval, rewrite approved input, or replay a stale decision.

Use stable request IDs for retries. A lost native response is uncertain, not proof of failure. Inspect rather than repeat. Native idle/done is not completion; report concrete checks and artifacts, then verify independently when required. Reconnect only to the user-selected live terminal and invalidate older task/approval state.

No automated worktree cleanup, Git integration, root revival, self-update or machine provisioning is part of this runtime. Use the appropriate native tools under the user's actual request.
